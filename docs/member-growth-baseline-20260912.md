# 经营基线第一阶段

## 范围与目的

仅修改 `/admin/users` 展示，新增 `MemberGrowthPanel`、`member-growth-core`、`member-growth-server` 和针对性测试。帮助管理员区分注册、真实付款与赠送权益，并优先服务即将到期和近期到期的付费用户。

无新增 API、数据库迁移、环境变量、依赖或定时任务。不调整价格、会员权益、交易开关、策略、预测记录；不自动联系用户、不投广告。

## 统计口径

- 滚动 7/30 天，截止时间显示为北京时间。
- 排除管理员、已识别的沙盒账户和测试付款。
- SQL `payment_orders` 和两处已存在的历史 Storage 文件只读加载。只使用已确认且有正付款金额、交易标识和有效确认时间的记录，不从有效会员状态推断付款。
- 同网络同交易去重；退款镜像排除；同交易关联不同用户则待核对，不重复计数。
- 历史付款与当前权益分别统计。首次已记录购买不保证是历史首购；重复购买不等于到期批次续费率。
- X 来源必须在注册前或注册时已记录；未知来源不倒推。小样本占比不是广告效果或因果证明。
- 读取失败、格式错误或超过分页上限显示“数据待核对”，不以零代替。现有记录覆盖不完整时不能当作完整经营账本。
- 未来 7 天到期、近 30 天到期列表仅展示有付款记录的账户，邮箱只出现在管理员页。
- 原有有效权益口径保留在折叠区并更正标签，不再叫付费转化率。

## 尚未完成的经营工作

历史应到期批次与续费率、收入对账、访问至注册漏斗、激活/再次使用事件、访谈及活动均不在本阶段交付范围。先取得本页面的实际数值再定增长实验；不承诺增长或收益。

## 验收与回滚

运行 `npx tsx --test tests/member-growth.test.ts tests/signup-attribution.test.ts`、`npm run typecheck`、`npm run build` 和影响审计。上线后还需管理员实际读取、未登录授权检查及只读升级验收；构建成功不代表生产验收完成。

回滚本提交即可恢复旧管理页面；无持久化数据写入，因此无需数据库回滚。不回退其他同时发布的交易或内容变更。
